# Desktop alpha 0.3 local behavior

Wire grammars remain YLang/YSL 0.1/0.2, YNP document v1 and PNG extension v2.
No new routing or crypto protocol is introduced. Exact identity-pinned TLS 1.3
remains mandatory for remote documents and PNGs, including through relays.

The existing bounded `YAMILIBRARY1` format accepts one optional row:

```
settings<TAB>ONBOARDED<TAB>LOCAL_ONLY<TAB>RELAY_FALLBACK
```

Each field is exactly `0` or `1`. Duplicate or invalid rows fail validation.
Older files without the row load as onboarding incomplete, local-only on, relays
off. Bookmarks/history retain their existing format. File limits, locking and
atomic replacement are inherited. A failed load is reported without overwriting
it. An explicitly selected config/network environment takes precedence for the
current session; UI changes save the resulting preferences locally.

Local-only allows built-in pages, legacy loopback YNP and loopback pinned TLS.
It rejects yami DHT navigation and non-loopback direct TLS before submission.
Switching to local-only cancels queued/resource work; already-started operations
remain bounded by the existing transport deadlines. No startup network request
is introduced. Startup does not open a host listener or start discovery.

Find operates only on shaped document buffers. Exact Unicode text occurrences
map through glyph byte ranges to highlight rectangles, including wrapped runs.
Search is case-sensitive, limited to 4096 occurrences, and excludes metadata,
link destinations and markup syntax. No search terms reach the resolver.

PNG decode reuse is RAM-only, per Loader, 16 entries and 16 MiB including encoded
bytes. Keys include destination identity, validated resource key and full fetched
bytes. A fresh authenticated fetch precedes every cache lookup. Per-page decode
budgets still apply to hits. No cached authentication assertion is shared between
node identities. Closing tabs cancels remaining resource work; active native
layouts are released on leaving Ready state.

`site setup` is an offline preparation command using existing authoring,
identity and strict config APIs. It uses create-new config output and
load-or-create identity, never replacement. Local preview/start is explicit;
public relay hosting additionally requires a configured exact relay pin.
`--probe` is an explicitly requested authenticated fetch, not a scanner or a
proof of independent networks. Versioned reports distinguish document/PNG
validation, native rendering NOT RUN and physical topology NOT VERIFIED.
